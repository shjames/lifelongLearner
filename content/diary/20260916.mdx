今天检出分支时，Git 没有直接报错退出，而是先给了一段 hint。

它想说的是：**你敲的这个分支名有歧义**。本地有一个同名分支，远程仓库（比如 origin）上也有一个同名分支，Git 不知道该检出哪一个，于是停下来先问清楚。

这不是错误，是提示。而且它顺带给了两条路。

**第一条路，把话说完整，直接指明检出的来源：**

```
git checkout --track origin/<name>
```

`--track` 的作用是，在检出远程分支的同时于本地建立跟踪关系。之后在这个分支上 pull / push，就不用再手动指定远端了。

**第二条路，把偏好写进配置，让它以后默认这么选：**

```
git config checkout.defaultRemote=origin
```

设完之后，再遇到同名分支，Git 默认认 origin，不再反问。相当于把「每次都要手动说明」变成「一次性把规矩讲清楚」。

## 被低估的 hint

其实 Git 的 hint 一直是被低估的东西。

很多人看到一大段 hint 就烦躁，直接去搜「git checkout 报错怎么解决」，抄一条命令了事。问题确实没了，但为什么出错、抄来的这条命令到底做了什么，还是不知道。下次换个场景，照旧卡住。

而 hint 里往往已经把原因、命令、配置项都给全了。它不是 Git 在添乱，是 Git 在解释。

**报错信息本身就是最好的文档。** 今天这次算是又一个例证——与其急着把红字消掉，不如先把它读完。
